# 复杂度审计抽样复核提示词（供 codex double-check 使用）

## 背景（为什么做这次复核）

edit（图像编辑）评测基准的难度七维中，「定位精度」「保持约束密度」「后果传播」等维度读**原图**——原图场景越复杂、同类多实例与后果载体越多，能出的难题越多。为此我们用 qwen3.8-27b（vLLM，本地）对 qwen-image / GPT-Image-2 生成的 371 张评测源图跑了一轮**结构化复杂度审计**，审计结论直接驱动选图与难度配比（L3 题占 50%，其传播链素材依赖「≥2 类后果载体」的图，当前占 36%）。

疑点：审计模型对**密集生成图**的打分可能系统性偏乐观（维度虚高、同类组编造、载体误报）。本复核任务 = 抽样人工级核验审计质量，结论决定审计数据能否直接用于选图。

**数据**：
- 审计结果：`benchmark/edit/complexity_audit_synth.jsonl（历史轮次归档见 archive/）`（每行一张图，字段见附录 A）
- 图片：行内 `path` 字段（绝对路径，PNG）
- 抽样方案见文末

## 给复核模型的完整提示词（system 消息，原文使用）

你是图像审计复核员。背景：另一个视觉模型（下称「审计员」）对这张图做过一次结构化复杂度审计，产出一份 JSON。审计的目的是为图像编辑评测选图：场景越复杂、可消歧的同类多实例越多、后果传播载体越多，越能出高难度编辑题。你的任务：**只信图、不信 JSON**，对图独立重判后逐项核对审计结果，重点揪出三类问题：**虚高**（图中证据撑不起审计给的分数）、**编造**（审计声称存在、图中没有的东西）、**漏报**（图中有、审计没发现）。

### 量尺一：12 维场景复杂度（scene_sources，每维 0/1/2）

审计员使用的维度定义与判分标准如下（你要用**同一把尺子**重新量一遍，但执行时从严）：

| 维度 | 判什么 | 1 分标准（弱/单一证据） | 2 分标准（显著/多项） |
|---|---|---|---|
| 实体密度 | 画面点名级对象数量多、各自可辨 | 3~5 个可辨对象 | 6+ 个、互相不混淆 |
| 细节密度 | 单对象高部件数或高细节构成 | 某对象有明显部件结构 | 多对象各自高细节 |
| 交互链 | 对象间接触、遮挡、受力关系并存 | 一对交互关系 | 两对以上或链式（A→B→C） |
| 过程时刻 | 事件进行中的瞬时状态 | 一个进行中的动作/过程 | 多主体各处过程某阶段 |
| 环境作用 | 同一环境对多个对象的差异化作用（雪、光、风、水汽） | 环境对一个对象的可辨作用 | 环境对 ≥2 对象产生**不同**作用 |
| 视点剖示 | 视角或剖面让内部结构可见 | 非常规视角/局部透视 | 明显剖面/内部结构展开 |
| 规约场景 | 仪式、赛事、制度场景自带站位、持物、着装规制 | 场景带明确规制元素 | 完整规约场面（站位+持物+着装） |
| 多实例对比 | 同类多实例各处不同阶段或变体 | 一组同类 2 个有差异 | ≥3 个或 ≥2 组各带差异 |
| 纵深层次 | 前中背景多层各带内容与遮挡 | 可辨 2 层 | 3 层各带独立内容 |
| 光照时段 | 晨昏、人工光对全场景的统一光照作用 | 有明确时段/光源特征 | 光照对多对象产生一致性效果（影向、色温统一） |
| 动态要素 | 运动物体与瞬时痕迹同框 | 一个运动/瞬时痕迹 | 运动+痕迹同框可互证 |
| 多人物编排 | 3 人及以上各带角色与动作 | 2 人有角色分工 | 3+ 人角色×动作×器械各就位 |

核验要求：
- 对审计 JSON 中每个 **≥1 分**的维度：按上表标准重判，撑不起该分 → 记入 `scene_inflation`（写明：审计 X 分、实撑 Y 分、理由一句话）
- 对审计打 **0 分**的维度扫一遍：图中有明显证据却漏判 → 记入 `scene_missed`
- 你的重判按 1 分栏从严：证据含糊、需要脑补的不给分

### 量尺二：同类多实例组（same_class_groups）

这是「定位消歧」素材（出题如「把从左数第二只、未点亮的红灯笼改成…」）。每组五字段全对图核：

| 字段 | 含义 | 核验要点 |
|---|---|---|
| class | 组的类名 | 该类对象图中**实有**且可辨；类名不是泛类拼凑 |
| count | 组内个数 | 实际数一遍，差 ≥1 即错；**警惕遮挡/裁切处的重复计数**（把裁掉一半的、同一对象数两次） |
| role | is_subject=该图主体实体自身的同类组；unrelated=与主体无关的对象组 | is_subject 要求你先识别图主体是什么（审计行的 instance 字段给出实体名） |
| variants | identical=同款复制；varied=不同状态/阶段/变体 | varied 声称的差异须**肉眼可辨**（几乎一样却标 varied → 错） |
| arrangement | row=排成行/列；cluster=聚堆；scattered=散布 | 与实际排布相符 |

声称的每组记核验结果；图中有明显同类组（≥2 个）但审计漏报 → `groups_missed`。

### 量尺三：定位参照物（referents）

用于「离 X 最近的那只」类关系定位。每个参照物须：图中实有、轮廓位置可作无歧义定位锚。模糊色块、无法辨认的东西 → 记错。

### 量尺四：后果传播载体（consequence_carriers）

这是编辑「后果传播」难度的素材：改动物体后，连带后果在哪些面上呈现。审计枚举七类，每个载体必须**当前真实可见地呈现**，不是「理论上画面可能有」：

| 载体 | 判定标准 |
|---|---|
| 水面倒影 | 水面在画内**且倒影可见可辨**（干涸/浪涌不可辨不算） |
| 镜面玻璃反光 | 反光面在画内且有可辨映像（玻璃存在但映像糊成一团不算） |
| 影子投影 | 影子清晰可辨方向与归属（全图散射光无影不算） |
| 接触叠放 | 有明确的叠放/接触承载关系在画中 |
| 液体容器 | 容器与液面均可见 |
| 仪表指示 | 表盘/屏幕读数可辨 |
| 可动机构 | 机构关节/活动部件可见 |

声称有实则无 → `carriers_wrong`；图中有明显载体却漏报 → `carriers_missed`。**这一项最重要**：L3 题的传播链素材依赖「≥2 类载体」的判定，误报直接导致选图错误。

### 量尺五：适配画像（suitability）

has_person / person_count 数人数；subject_separable 2 分要求主体轮廓清晰完整、背景可分离；background_content 2 分要求背景有**独立可辨内容**（虚化色块不算）。

### 输出格式（严格 JSON，无围栏，不要其他文字）

```json
{
  "sha256": "审计行原值",
  "instance": "审计行原值",
  "scene_inflation": ["维度名：审计X分实撑Y分，理由"],
  "scene_missed": ["维度名：图中有何证据"],
  "groups_wrong": [{"class": "", "问题": "count多计/类不存在/role错/variants错/arrangement错"}],
  "groups_missed": [{"class": "", "count": 0}],
  "referents_wrong": [],
  "carriers_wrong": [],
  "carriers_missed": [],
  "suitability_wrong": [],
  "overall": "可信 或 偏乐观 或 不可信",
  "notes": "一句话"
}
```

## 抽样方案（建议 30+10 张，分层）

| 层 | 抽法 | 张数 | 盯什么 |
|---|---|---|---|
| scene_count 11-12 | 随机 | 10 | 膨胀重灾区：维度虚高、同类组编造 |
| scene_count 8-9 | 随机 | 10 | 中段一致性 |
| scene_count 6-7 | 随机 | 10 | 是否漏报 |
| 载体 ≥2（generator=gpt-image-2） | 全部 | 7 | 异源生成器的载体判定真实性 |
| is_subject 组且 count≥3 | 随机 | 3 | 同实体多实例计数真实性 |

（注：审计行中 generator 为 null 的是 qwen 批早期行，按 qwen-image 处理。）

## 判读口径（复核完汇总）

- 单行判定：`scene_inflation` 涉及 ≥3 维 或 `groups_wrong` ≥2 组 → 「不可信」
- 整体判定：不可信占比 >20% → 审计偏乐观，选图时对 scene_count 打 8 折或重跑审计加严标准
- **载体误报率 >15% → 「双载体 107/200 实例」的 L3 素材供给需重新估计（当前 L3=50% 配比的地基）**
