# 图像编辑出题协议（v6.1 simple 补充配置）

本配置沿用 v6.1 的看图证据、九类编辑语义和 JSON 契约，但用于少量简单场景题。只做一个清楚的主操作（compose 为两个），不为复杂度增加物体、关系或隐藏要求。全部源图事实仍须亲自看图核验。

输入中的 level 是原 T2I 参考标签，原样回显，仅用于实例对齐，不表示该编辑题难度。suite 固定 basic。忽略参考层级对应的旧多跳、场景数、知识数与义务数量门槛，本配置不采用这些门槛。

## 1. 证据优先级（硬约束）

1. **原图像素是原图事实的唯一来源。** 只有你亲自在图中高置信确认的对象、属性、数量、方位、遮挡、影子、倒影、接触面和背景区域，才能用于定位、推理、保持或负向约束。
2. `caption`、生成 prompt、素材清单、审计摘要、分类路径都只是**待核验假设**；`desc` 只可辅助回忆公认世界知识。它们都不能证明某物在图中可见。文本与图冲突时以图为准；图中不清楚时视为没有证据。
3. 每个依赖原图的目标、定位锚、干扰项、后果载体、保持对象和混淆源，都必须有 `evidence_receipt`。回执的 `source` 只能是 `image`，`confidence` 只能是 `high`。无法给出高置信回执的要素必须删除；删除后达不到门槛则输出 `cannot_construct`。
4. 上述限制只约束**源图事实**。`add`、`replace`、`background` 等类型本来就允许在结果图中新建源图中不存在的内容；新内容本身不需源图回执，但它依附的源图位置、表面、边界或参照物需要回执。
5. 不得把“看起来像”“可能是”提升为事实，不得用辅助文本补足被遮挡、模糊或画外信息。

输入的分类路径通常形如 `demiwtg / 主域 / ...`。主域以输入明确给出的 `main_domain` 为准；没有该字段时才取路径的第二段。路径仅提供知识语境，不证明画面内容。

## 2. 九类编辑的严格语义

`edit_type` 必须与 `target_edit_type` 完全相同；不适配时不得换类型。

| edit_type | 必须做什么 | 不得偷换成什么 |
|---|---|---|
| `replace` | 删除一个已定位的源图对象，并在同一语义槽位放入指定新对象；透视、尺度、遮挡和接触关系与该槽位一致 | 仅覆盖贴图、保留旧对象残片、顺带换掉同类对象 |
| `add` | 在指定位置新增对象，同时保留原有对象；新增对象与可见表面、遮挡和光照关系一致 | 以新增为名替换或擦除既有对象 |
| `remove` | 移除已定位对象，并依据周围可见纹理连续补全暴露区域 | 猜测并规定原图不可见的隐藏细节，或把目标模糊掉 |
| `adjust` | 只改变既有目标的指定属性或状态；未被指令改变的身份、数量、几何和位置保持 | 用另一个对象替换目标，或擅自改变轮廓/数量 |
| `background` | 只替换或修改背景区域；全部前景实例的身份、数量、姿态、几何、位置、内部外观和遮挡关系保持，边界干净 | 重绘、增删、移位或重打光前景；若所选环境变化必然要求前景联动，应判为类型不适配 |
| `action` | 改变一个可见人物或动物的动作/表情，并更新其自身关节、遮挡与接触关系 | 换人/换动物、换服装、换镜头或改背景 |
| `style` | 仅凭题面文字指定整体视觉风格；全图语义内容、对象数、布局、姿态、几何和机位保持 | 假设存在风格参考图，或借风格迁移增删对象。该类型输入只有“原图 + 文本条件”，没有参考风格图 |
| `extract` | 从原图提取一个高置信可定位目标，输出其**源图可见部分**与干净边缘，背景为纯白，其他内容全部移除 | 幻造被遮挡部分、改造目标、保留原场景或使用透明/灰色背景。该类型目标是“原图目标 + 白底输出” |
| `compose` | 恰好两个操作，作用于两个不同且有回执的目标；子操作只能取 `replace/add/remove/adjust/action`，两者都完整执行 | 对同一目标换说法凑两步，或夹带第三个操作、`style/extract/background` 子操作 |

非 `compose` 只允许一个主操作。指令应只有一种定位解析和一种操作目标；保持范围用一句最小化表述圈定。简单题可以在题面直接写明验收要求，不要求刻意隐藏后果。


## 简单题构造与核验

- 选择明确可定位的目标，指令简短、单义、可执行。直接改色、移除一个物体、替换物体或背景、提取目标都可以；不强迫知识谜题、多对象互动或物理连锁。
- reasoning 按行写 [结论] R1…、[保持] P1…、可选 [不得画] N1…，各组编号从1连续。至少一个结果要求、一个具体保持要求；显式主操作可以作为 R1，不要求另造隐式结果。N 项只在有真实混淆风险时写，写时注明混淆源。
- 推理无需多跳，可以直接写可核验要求，最长跳数可为0；如写箭头，每个箭头必须有真实推导，level_reason.longest_hops 等于单行最多箭头数。只在实际引用知识时写（知识·类别；域·知识域），否则 knowledge_categories/knowledge_domains/hop_types 可以为空。
- 定位方式、保持类别、前提类别、weak_points 至少各写一个适用项；scene_types 按像素事实填写，可以为空，不凑复杂度；consequence_types 只记真实发生的必要传播，可以为空。style/extract/background 须至少填一个本类型的 special_obligation_types，其他类型该数组为空。
- 不要求弱点乘积，product_checks 必须为空。level_reason 中各计数精确对应实际数组、R/P/N 与箭头，meets_target 表示满足本 simple 配置。
- 保留对源图身份、可读细节和非目标内容的核验，不用“其余不变”代替具体保持证据。低复杂度不是 cannot_construct 的理由；目标不清楚、指令不适配或无法可靠验收时，仍可按不可出题契约返回。
- 所有源图断言必须被 evidence_audit 与 evidence_receipt 覆盖。削峰禁令仍对实际采用的后果传播类型有效；无需传播的直接编辑不得伪造传播来填数组。

## 6. 封闭枚举（禁止自造、缩写或近义改名）

- `targeting_types`：`唯一属性直指`、`属性组合`、`序数定位`、`方位定位`、`部位定位`、`关系定位`、`全局范围`
- `consequence_types`：`光影联动`、`倒影同步`、`接触受力`、`计数联动`、`材质互动`、`液流运动`、`磨损老化`、`生态反应`、`状态指示`、`气象温度`、`空间补全`、`纹理透视`
- `special_obligation_types`：`风格笔触`、`风格色彩`、`风格明暗`、`风格材质`、`主体完整`、`抠图边界`、`白底纯净`、`杂物清除`、`背景语义`、`背景透视`、`背景景深`、`前景边界`
- `preservation_types`：`无关区域保持`、`计数布局保持`、`主体身份保持`、`姿态视角保持`、`全局光照保持`、`风格媒介保持`、`色调氛围保持`、`物理属性保持`
- `premise_types`：`定位前提`、`改动规定前提`、`保持范围前提`、`环境场所前提`、`时间阶段前提`、`数量编组前提`、`视角取景前提`
- `knowledge_categories`：`概念自身结构`、`状态与阶段`、`环境交互`、`可组合关系`、`规约与典故`、`物理规律`、`化学规律`、`生物规律`、`地理气象`、`天文对应`
- `hop_types`：`过程-因果`、`规约-标准`、`发育-生长`、`功能-结构`、`物理规律`、`文化-规制`、`关系（组合）`、`分类-辨识`、`量-守恒`、`序-时序`、`原理-推演`、`化学-反应`、`生态-互动`
- `scene_types`：`实体密度`、`细节密度`、`交互链`、`过程时刻`、`环境作用`、`视点剖示`、`规约场景`、`多实例对比`、`纵深层次`、`光照时段`、`动态要素`、`多人物编排`
- `weak_points`：`过度编辑`、`改动遗漏`、`后果缺失`、`定位错改`、`身份漂移`、`计数漂移`、`光影不一致`、`倒影失同步`、`接触悬浮`、`字样崩坏`、`边缘伪影`、`材质失真`、`姿态崩坏`、`背景重绘`、`构图漂移`、`色调漂移`
- `knowledge_domains`：`政治、法律与社会制度`、`地理与地点`、`宗教与信仰`、`民族、语言与文化`、`人造物体`、`动物`、`真菌与微生物`、`植物`、`人物与人体`、`行为动作`、`食物`、`建筑与基础设施`、`交通工具`、`自然景观`、`场景`、`节日与符号`、`属性与状态`、`材料与物质`、`时间数量与度量`、`文字与信息图形`、`声音`、`文化艺术与媒介`、`知识与学科`、`组织机构与社会事件`、`体育与游戏`、`历史与时代`、`品牌与产品`、`数字与互联网文化`、`医学与健康`

辅助字段中的 `used_in` 不是类别标签：它只能写 `edit_instruction` 或本题实际存在的终端编号（如 `R1`、`P2`、`N1`）。

## 7. evidence 审计与回执

先看图，再设计题目。`evidence_audit` 的每条事实使用唯一 `Vn`：

- `visible_facts`：只列高置信可见事实，每项含 `id`、`fact`、`anchor`。
- `edit_targets`：引用可作为源图目标的 `Vn`。
- `distractors`：引用真实干扰项的 `Vn`；没有就用空数组，不得虚构来凑定位。
- `uncertain_or_rejected`：记录辅助文本提出、但图中看不清或与图冲突而被弃用的候选；没有则为空数组。这里的内容不得出现在题面或推理中。

`evidence_receipt` 每项必须完整包含：

```json
{"element":"V1: 事实的简短名称","anchor":"可在图中复核的具体方位或相对位置","used_in":["edit_instruction","R1"],"source":"image","confidence":"high"}
```

`anchor` 不能写“见图”“如 caption 所述”或文本字段名。回执要覆盖：

- 指令中的所有源图目标与定位锚；
- reasoning 使用的每个可见载体、保持对象/区域、干扰项与混淆源；
- `scene_types` 所依赖的可见场景证据。

同一可见要素可由一条回执覆盖多个 `used_in`，但不得用一条含糊总括回执覆盖互不相干的要素。结果中新建对象、纯世界知识节点和题面明确指定的新状态不伪造图片回执。

## 8. constructed 输出契约

所有字段都必须出现；数组去重，顺序按推理首次使用。`level_reason` 中的计数必须与实际终端、数组和链一致。

  "level": "输入 target_level 原样",

## 9. cannot_construct 输出契约

出现任一情况就不可出题：指定类型与图不适配；目标/锚/载体无法高置信看清；knowledge 结果不唯一；无法遵守削峰禁令。不得换图、换类型、用辅助文本补证据。

`cannot_reason_code` 只能是：`target_not_visible`、`target_ambiguous`、`type_incompatible`、`insufficient_evidence`、`insufficient_level_support`、`knowledge_not_unique`、`ban_conflict`。

```json
{
  "task": "edit",
  "qid": "输入 qid 原样",
  "status": "cannot_construct",
  "edit_instruction": "",
  "edit_type": "输入 target_edit_type 原样",
  "suite": "输入 suite 原样",
  "level": "",
  "level_reason": {},
  "targeting_types": [],
  "consequence_types": [],
  "special_obligation_types": [],
  "preservation_types": [],
  "premise_types": [],
  "hop_types": [],
  "scene_types": [],
  "knowledge_categories": [],
  "knowledge_domains": [],
  "weak_points": [],
  "product_checks": [],
  "evidence_audit": {"visible_facts": [], "edit_targets": [], "distractors": [], "uncertain_or_rejected": []},
  "evidence_receipt": [],
  "reasoning": "",
  "notes": "具体说明为什么无法合规构造",
  "cannot_reason_code": "上述封闭枚举之一"
}
```


## 交题前回验

检查目标真实可辨、操作明确、保持项可核验、编号与计数一致、回执引用存在、数组取自封闭枚举。只输出一个完整严格 JSON 对象，不输出围栏或说明。


样本编号：e104
【题目编号（qid）】e104
【先看图】请先独立检查随附原图，再读取以下文字辅助。原图像素是源场景唯一事实；文字不能把看不见或看不清的东西变成事实。
【实体名】花笼
【实体知识（只可定义概念/目标态，不可证明图中存在）】（无 desc）
【caption（高风险待核假设，不可作图面证据）】（无）
【批次主域】植物（分类路径以 demiwtg 为根，主域是其后的第二段，不是字面首段）
【分类路径】
demiwtg / 植物 / 多肉与仙人掌植物 / 仙人掌类
【目标编辑类型】background（必须出该类型；与图内容不适配时走不可出题分支，不得硬出）
【套系】basic（直接编辑套）
【T2I 参考层级】L2（仅照抄到 level 作实例对齐标签，不是本题难度；本题采用 simple 配置，不要求该层级的多跳或义务计数）
【素材清单】
初审素材（模型审计产出，已知含 10%~40% 虚项，仅供定位参考）：
- 场景维度（+号=自报强项，环境作用/过程时刻为高虚报维度，引用须给图面证据）：实体密度+、细节密度+、交互链、多实例对比+、纵深层次
- 同类组（count 与 role 常有误报，计数不得直接入题面）：铺面石子×35(unrelated)
- 参照物（复核实证最可靠字段）：花笼仙人掌、上方浅色大石、右上深灰石块
- 后果载体（约 11% 虚报）：接触叠放

【辅助信息纪律】原图像素是源场景唯一事实。实体 desc 可提供世界知识，caption、分类路径和素材清单只提供待核假设；它们都不能证明对象、数量、方位、文字、影子、倒影、接触点或环境在图中存在。任何冲突以图为准；看不清即视为不可用，不猜、不补。初审计数不得直接进题面（要计数须自己数图）；count>10 的组或密集人群不得作为「第 N 个」序数定位锚。
【证据回执再强调】题面和 reasoning 使用的每个源图目标、定位锚、干扰项、后果载体与具体保持对象，都须逐项进入 evidence_receipt；每项含 element、anchor、used_in、source="image"、confidence="high"。新增目标态与图外公认知识不冒充源图证据。
【削峰禁令】不得使用的后果传播类型：光影联动、纹理透视。（后果类型禁令为硬约束，确实无法不破禁出题时输出 cannot_construct，不得硬凑；域避让为软约束，无等价替代知识来源时可不用）
请按出题指令对这张原图出 1 道题，严格执行交题前自查清单，只输出一个严格 JSON 对象，不要任何其他文字。

【既有机审要求自查】
本题 targeting_types 至少 1 种、weak_points 至少 1 种，均须在题面/推理中真实使用并有对应证据，不可只加标签。
level_reason.longest_hops 等于 reasoning 每行箭头数的最大值，每个 → 或 -> 均计一跳，包括终端前的箭头；每个非空行恰有一个 [结论] Rn、[保持] Pn 或 [不得画] Nn 终端。
知识节点按（知识·类别；域·知识域）独立标注，括号中不得在知识·之前加推导类型；knowledge_categories 与这些知识类别去重集合一致。
evidence_receipt.used_in 只能包含 edit_instruction 或实际 R/P/N 编号；edit_targets 中每个 Vn 都须有 used_in 包含 edit_instruction 的回执。
