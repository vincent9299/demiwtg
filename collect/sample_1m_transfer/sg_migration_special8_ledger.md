# SG 迁移特殊 8 对象留档（unreachable keys）

日期：2026-09-25　记录人：迁移编排会话（sess_2c81da3e 续）

## 现象
旧 SG 桶 lhcos-368f6-1256345599 中存在 8 个对象，key 内含真实 TAB 字符及
粘杂物（`Q<数字>` / `pid:<数字>` + 另一条记录的文件名/扩展名），系当年某次
上传拼坏 key 所致。它们污染了 sg_inventory.tsv 及 5 个迁移分片
（mig_04/12/18/28/38 各含 2/2/1/1/2 行），导致对应机器 worker 启动即
ValueError（int(size) 解析到文件名）。

## 处置
1. 8 个 sha 均不在 manifest_1m_v2all.tsv（SH 同步清单）内 → 属迁移范围，非误路由。
2. 5 个分片已净化（仅删除这 8 行）后重新分发，新基准 md5 已更新 mig_ref.md5。
   迁移分片总量 8,815,260 → 8,815,252；8 个特殊对象单独处理。
3. 特殊对象 API 迁移尝试全部失败（详见下），定性：**可列举、不可寻址**。
   保留在旧桶，等待人工决策（接受 ~230MB 损失，或提腾讯工单服务端处理）。

## 尝试过的寻址方式（均 404 / NoSuchKey，签名均通过）
- HEAD/GET 引码 path（%09/%20）+ 引码签名（cosio 原生）：HEAD 404 / GET 403
- GET 引码 URL + 原始 path 签名：404
- 原始 socket 请求行：真实 TAB+真实空格（签名同形）：404
- 原始 socket：真实 TAB + %20 空格：404
- 原始 socket：全引码：404
- URL=raw 形态 + 引码签名交叉：404
- CopyObject（x-cos-copy-source 引码源 key，头不参与签名）：NoSuchKey
- ListObjectsV2 前缀列举：**能列出**（key 含真实 TAB，Size 与清单一致）
