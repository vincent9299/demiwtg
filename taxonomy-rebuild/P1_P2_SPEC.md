# 视觉概念核验：P1 → P2 实施规范

本规范遵循 [项目 Pipeline 强制规范](../PIPELINE_SPEC.md)。它汇总 2026-10-01 以前的讨论及用户最新确认，规定 `preparation/concepts` 的业务行为，以及为它补齐的 demiflow 通用能力。历史讨论保留在 [执行约定](EXECUTION_PLAN.md)，发生表述冲突时以本规范和用户后续明确指示为准。本文是实现与验收依据，不是已经完成真实模型质量验收的声明。

用户已授权完整实现、隔离验证与 review。输入由配置指定，不固定为 3,315 条。旧树中的 3,315 个名称只是后续可能使用的一批输入；旧分类是待核线索，不约束新树。用户随后授权小规模真实模型与下载验证及性能采集；不代为启动全批，不迁移生产文档，不改写公共概念或图片表。开发中的模拟响应只能检验程序契约，不能证明模型判断正确。

## 1. 目标、主体和边界

本流程回答：原名称究竟指什么，指代和范围是否能得到证据支持，哪些核心事实已经核实，这些事实是否支持有意义的视觉任务方向。它不要求每个有效概念都是生物物种，也不因一个名称常见就免除核验。

科、属、种、品种、性别和生长阶段可以各自构成有效的生物概念。器具类别、系列、型号，人物角色、动作、关系、虚构对象和组合场景也可能成立。对象类型是开放的语义描述，不以一个穷尽枚举强行划分。生物分类等级另有字段，不能把“名称成立”写成“已经核验到种”。

概念身份、核心事实、视觉任务潜力和程序执行状态分别表达。身份明确但视觉资料不足，可以保留身份结论并在后续建树时使用，出题暂缓。身份不明的概念保留待核。改名只有语义等价时才可沿用原身份；范围变化、拆分或合并不能自动继承原图片或直接采纳。

P1 提出核验计划，P2 依据实际交付的材料审定。规则负责协议、限额和技术状态，不负责把“简单概念”判真、把“难概念”交给模型。两轮 P2 使用同一角色和协议。没有独立网页评审模型、模型摘要、粗筛或精筛节点。正式 T2I 出题仍在后续 P5；P2 最多交付一个简短任务方向，不在这里生成训练题。

## 2. 流程与行粒度

```mermaid
flowchart LR
  I[配置选择的概念输入] --> P1[P1 提出核验计划]
  P1 --> S[搜索]
  S --> F[获取与结构化解析]
  F --> R[读取与材料编排]
  R --> A[P2 首轮审定]
  A --> B{有有效补查请求}
  B -->|有| S2[执行一次有界补查]
  S2 --> A2[同一个 P2 再审定]
  B -->|无| O[最终核验记录]
  A2 --> O
```

主数据流始终一行代表一个原始概念身份；节点中的查询、候选网页、文档和阅读块是该行的有界列表。不同概念可并发，同一概念内部的搜索和获取也可并发。主线不展开成网页行再归并，算子内部不创建子 Dataset，不扫描全库。

各节点通过有界队列连接，并在交接时完成对应阶段的小批持久化。某个概念完成 P1 后即可进入搜索，不等待整批 P1 完成。无需补查的概念保留原行并跳过补查处理；只要求补读的概念跳过补查搜索和下载。正常完成时所有输入均进入最终记录，失败、未决、超额和没有资料都不得从分母删除。全局故障中断时保留已提交的小批和固定输入选择，明确记录范围与未完成状态，不为尚未执行的概念伪造判断。

补查最多一轮。首轮 P2 的有效结论和补查计划分别保存；补查后仍无结论，记录核验未决和缺口，不继续循环。第二轮技术失败时保留首轮有效判断，同时明确本轮技术未完成，不能用首轮成功掩盖失败。

## 3. 输入、身份和旧材料

正式入口为 `concepts_pipeline.config → run_pipeline`，CLI 和 notebook 调用同一入口。配置指定固定的源 URI 与版本，可选明确名称集合，并设置最大输入数作为安全上限。未指定集合表示使用固定源的全部记录；超出上限报错，不静默抽样。显式选择的名称缺失、源键重复或源不可读，在调用模型前报告。

读取字段由输入映射明确指定，至少有原名称；别名、旧分类、QID、多语言名称、文字说明和文档定位信息仅在源中实际存在并被配置映射时传入。额外线索采用“字段名、值、来源”的结构，不推断未提供字段。旧 taxonomy 原值和解析后的完整路径都保留，避免错误拆成同一级标签。

`source_record_id` 和 `concept_id` 绑定原来源键，规范名、模型判断、树位置和重跑版本不会改变身份。结果始终携带 original_name、source 与 name_relation；已有图片仍按原名或原身份关联。同义名称规范化不是图片已复审的证明。跨源键或原名变更需要显式身份迁移，不在本版自动执行。

第一版不自动加载历史下载文档的正文。标题、URL、QID 和定位信息是检索线索，不等于已经读取对应资料。后续历史正文接入时复用独立文档与阅读契约，不要求先重写整个 collect，也不绕过 P2 审定。

## 4. P1 的输入、职责与校验

P1 结合输入线索和“你掌握的相关知识”提出核验计划；这里“你”指执行 P1 的模型。输入资料与模型知识都可能错误，两者都不是已核证据。提示词要求模型主动检查歧义、范围、分类等级和遗漏，不能只围绕已有材料寻找支持。

P1 输出最多 4 个候选解释、最多 8 个非空核验问题或待核断言，以及有限查询计划。即使模型很有把握，仍保留需要证实的断言；不强行制造疑问，也不能跳过取证。查询可以为空，程序始终保留原名查询；模型另给最多 3 个查询。每个查询关联一个或多个问题编号。

核验至少覆盖对身份和范围有决定作用的内容，并考虑核心内容和视觉应用所需的关键事实。例如原名是否确指候选学名，与候选物种有哪些形态特征是不同问题；仅搜索候选学名不能证明原中文名称指向它。器具型号、角色限定、雌雄或生长阶段也需要确认限定的真实含义及适用范围。

程序检查字段类型、必填内容、数量、问题 ID 唯一性和查询关联，不判定问题语义是否充分。问题质量由 P2 的补充、后续人工复核和真实质量评测检查。协议无效保留原响应并记技术失败，不通过隐藏模型调用修复。

## 5. 搜索与获取

首轮每概念最多 4 个去重查询，包含原名。相同查询可合并执行，但全部问题和概念关联必须保留。每查询使用搜索服务返回顺序中的前 5 个不同、有效的 HTTP(S) URL；在这些候选内最多取得 2 份技术上可读的文档。候选摘要和标题不升级成正文证据。

不按名称或标题命中分数淘汰结果；语言不同、别名未出现都不是技术淘汰依据。旧 collect 的别名漏传导致正确英文材料被过滤的问题留在其标准化 TODO，新的取证路径不采用该过滤逻辑。电商、厂家和商业域名不一概排除，是否相关和可信由 P2 按具体核验问题判断。

程序可以排除无效 URL、重复候选和明确不可用的技术返回。获取失败时在候选配额内继续尝试；不能扩展到无限候选。共享 URL 只获取一次，但每个概念及查询仍有自己的使用记录。文档按原查询和候选顺序交付，关联问题与查询按确定顺序排列，不能让下载完成顺序改变模型输入。成功获取与成功解答问题是两回事。

第一版支持 HTML 和纯文本。PDF、OCR、需要浏览器执行 JavaScript 的内容和图片正文识别不自动启用，明确返回不支持或无可读正文。技术状态至少区分可读、无结果、网络失败、HTTP 错误、限流、内容过大、格式不支持、登录或验证码阻断、空正文及解析失败。

HTML 提取按页面结构去除导航、页脚、Cookie 提示、侧栏广告和相关推荐等模板内容。来源标题、作者、日期单独保存；正文章节标题、表头、图注和有意义的上下文保留。显著结构标记有助于提取，但不保证所有广告都能机械识别。语义可疑、重复拼接或伪造正文交给 P2 判断；原始快照始终可追溯。

## 6. 独立文档与引用契约

网页内容不保存在 Lance 表中，也不通过某张 Lance 材料表的记录间接读取。所有消费者统一引用独立、不可变的文档对象。引用基本字段是普通 `uri` 与内容 `sha256`；读取先检查结构和散列，不能把线上原 URL 当成冻结文档 URI。

一个文档包含：schema_version、原 URL 与最终 URL、获取时间、内容类型及来源标题等信息、raw_ref、解析器名称与版本及配置摘要、按原顺序排列的章节和文本块。每块有固定 ID、类型、正文和章节路径；表格和图注保留必要语境。块 ID 只在该文档内容版本内有效。

原始响应字节和规范化 JSON 都保存为独立对象，规范化 JSON 使用 UTF-8。解析器或内容变化生成新对象，不能原址覆盖已有引用。文件先原子发布并验证，之后阶段表才提交引用；阶段表提交确认后才向下游交付该行。存储采用内容散列去重，可由多个概念或表共享；被引用对象不是可随意删除的缓存。

Lance 仅保存概念业务结果、文档引用、实际阅读的块 ID 与顺序、问题关联、未读范围、技术状态和预算用量。实际模型请求文本可以进入原生 SQLite 调用日志以便回放；这是请求审计，不新增一个文档正文业务数据库。原始资料不复制到各阶段表中。

## 7. 阅读与 P2 材料编排

读取器按核验问题和文档结构选择原文块，首轮材料最多 12,000 tokens。选择不是相关性审定：它是预算下的可追溯阅读安排。各问题轮流获得候选片段，避免身份问题占用全部预算；正文位置、章节标题、命中片段的必要相邻段落一起考虑。不能只取各文档开头，也不能用模型摘要代替原文。

每个交付块都有唯一引用 ID、对应文档 URI/散列、原块 ID、来源信息及关联问题。预算包括材料中的来源和上下文包装。块超过剩余预算时不隐式裁切或伪称已完整阅读：跳过该块并记录未读范围。保留文档目录和未读块定位信息，供 P2 有目的地补读。目录、标题、搜索摘要不属于可引用的正文。

P2 只能引用本次输入实际包含的块。程序对引用存在性和读取身份作严格校验；引用正确存在不等于其语义支持结论，支持关系、否定、适用条件和来源可信度由 P2 判断。不同网站转载同一来源不能当作独立证实，也不设置“至少两个网站才通过”的机械门槛。

首轮 P2 接收原始线索、P1 计划、已读材料、查询与获取状态、未读范围及剩余额度。第二轮还接收首轮判断、其补查请求、执行回执、旧材料与新材料。新材料最多 6,000 tokens；第二轮总材料最多 18,000 tokens，完整输入最多 32,000 tokens。阅读阶段用同一份原生 prompt、响应 schema 和计数档案预留完整请求的空间。12,000/6,000/18,000 都是材料上限，不要求填满；完整请求需要更多空间时，重新安排本轮新增完整块，并在 reading.reason 说明额度收缩和未读范围。之前已经交付的材料、首轮结论、失败回执和必要上下文全部保留。本地先检查全部新增额度；超额时检查零新增材料，再至多进行六次额度二分检查，只交付实际计数满足输入上限的结果，不增加模型调用；即使不增加材料仍超额，就明确记录输入预算不足，不静默删去先前反证或失败记录。

## 8. P2 的输出与边界

P2 每次输出三部分：逐问题结果、当前概念结论和补查请求。

逐问题结果包含问题 ID、问题文本、answered/unresolved/not_applicable、回答、实际阅读块引用和缺口。不适用必须说明原因。必须覆盖 P1 的问题，允许补入遗漏问题，但不改写已有 ID 的含义。不能按回答个数或比例自动决定概念成立。

当前结论包含身份状态、规范名、定义、对象类型、限定、名称关系、生物等级、身份依据、核心事实、视觉任务状态和理由。每个核心事实有内容、成立条件、允许变化及证据引用。视觉任务方向基于这些事实，区分材料直接支持的事实与出题设计推断；没有实际看图，不能声称已确认图片质量或辨识度。

身份 resolved 需要非空身份依据和明确指代。name_relation 为 unchanged 时规范名必须逐字等于原名；equivalent 只表示语义不变的规范化；scope_change 明确指出范围改变，不能自动采纳、挂载或沿用旧图；unresolved 表示名称关系尚未解决。

task_status 为 ready 时需身份明确、名称关系未改变范围、引用已核事实，并交付简短方向、条件、视觉检查点、实质性错误和允许变化。hold 时保留原因，不虚构任务草案。一个对象为科或属并不自动导致 hold，也不意味着可任意选一个种代替它。

部分网页失败时，成功材料和失败记录一起交给 P2。正常搜索无结果也可以形成有效的未决判断；它不是不存在的证明。所有取证尝试均因技术原因失败且没有可读材料时，不伪造正常空证据审定，记录技术未完成。

## 9. 补查计划、额度和停止

首轮 P2 按优先顺序列出请求，每项关联问题和具体缺口。请求类型为新查询、获取已经发现但未取回的候选 URL、读取已经保存文档的指定块或章节。URL 和文档定位必须来自本概念已交付候选，不允许模型凭空捏造定位。需要作者解释或原始上下文时记录缺口，不制造无目的检索。

一轮补查最多 2 个新查询，每查询前 5 个不同候选；整轮最多尝试 5 个不同 URL，包含直接要求获取的已知候选；整轮最多新增 2 份可读文档，不能误写成每查询 2 份。已有文档最多 3 个补读请求。请求可以列出 block_ids，也可以用 section_id 指定章节标题块；章节展开包含子节，停止于下一个同级或更高标题，仍共用这一项请求和阅读 token 预算。新文档和旧文档补读共享 6,000 token 新材料预算。

请求按 P2 优先顺序消费配额，可以混合类型，不强迫用完。超过额度、重复、定位无效、技术失败和预算不足分别记录，不能静默忽略。技术重试不会增加语义补查轮次，也不会扩展候选和文档额度。第二轮 P2 无论结论如何都结束本轮；若仍提出后续需求，只记录为以后处理的缺口，不继续执行。

## 10. 默认运行参数

各节点的外层并发单位是概念。下表是已接受的起始值，可在配置中分别调整，不能据此保证某个吞吐或完成时间。

| 节点 | 外层并发 | 队列深度 | 单概念内部并发 |
| --- | ---: | ---: | ---: |
| P1 | 4 | 4 | 无嵌套模型调用 |
| 搜索 | 8 | 8 | 2 个查询 |
| 获取与解析 | 8 | 8 | 2 个网页 |
| 读取与编排 | 4 | 4 | 2 个文档 |
| 首轮 P2 | 4 | 4 | 无嵌套模型调用 |
| 补查搜索、获取、读取 | 同首轮对应节点 | 同首轮对应节点 | 同首轮对应节点 |
| 第二轮 P2 | 4 | 4 | 无嵌套模型调用 |
| 每张阶段表的提交者 | 1 | 64 | 每批最多 32 行，或首行等待 5 秒即提交 |

同一运行共享模型请求上限 8、搜索请求上限 8、网页获取上限 16；单网页主机最多 2 个请求在途，并限制每秒启动 1 次请求。共享限额覆盖首轮和补查，不因算子不同叠加放大。队列等待与资源准入等待单独计时，请求超时从获得执行资源后开始。

| 限制 | 默认值及含义 |
| --- | --- |
| 连接超时 | 10 秒 |
| 每次搜索或获取 | 总计 30 秒，包含连接、重定向与响应读取 |
| 解析或读取 | 30 秒；阻塞工作必须有可终止的执行边界，不能声称取消 await 已杀死线程 |
| 模型请求 | 600 秒；不包含排队时间 |
| 存储锁等待 | SQLite 等存储锁最多等待 30 秒；同 run 的写入所有权锁保持立即拒绝第二个写入者，不隐式排队启动另一批 |
| 网页字节 | 每次尝试压缩传输累计与解压后累计各最多 2 MiB，包含重定向响应 |
| 规范化文档 | 最多 8 MiB |
| 重定向 | 最多 3 次，共用单次 30 秒总期限 |
| 搜索/获取瞬时网络失败 | 最多重试 1 次，共 2 次尝试；正常退避约 2 秒加抖动 |
| 429 | 遵守 Retry-After；超过 60 秒则记录限流，不提前重试 |
| 404、验证码、登录页、空正文、不支持格式 | 不对同请求技术重试，可按配额尝试下一候选 |
| 模型传输与输出协议重试 | 0；请求结果不明确时不得盲目重发。此前发现的 LiteLLM 默认两次重试，现通过平台显式 gateway 适配在请求上关闭 router/SDK 重试与 fallback；实际尝试头保留，供应商内部行为仍不可由客户端证明。 |
| 文档散列、解析和文件错误 | 0；保留明确失败原因 |

模型或搜索服务鉴权错误、错误模型名、无法写入存储等全局问题停止新的调度。同一模型或搜索服务连续 5 次连接错误、408、5xx 或 429 且中间没有成功响应，停止新请求。单个网站失败不触发全局服务故障。网页出网代理通过 fetch_proxy_url 显式配置，默认直接连接；不隐式继承进程代理，也不把本地搜索服务送入网页代理。代理地址禁止内嵌凭据，并进入获取请求身份。更改传输路由属于一次显式新获取配置，旧失败回执仍保留，不能宣称原路由已成功。已完成结果保留，不能把这类中止解释为所有剩余概念无效。

模型传输采用 demiflow 原生 `map_prompt_async(options=...)`，业务默认 stream=True、gateway=litellm；平台通用默认仍为非流式。模型连接/读空闲/上传/连接池等待/总时限分别为 10/120/30/30/600 秒，与网页获取超时分开。节点复用一个有界 HTTP 池，每个概念独立组装，共享请求许可一直持有到响应保存完成。原始 SSE 日志默认关闭；失败部分内容留在原生日志，表中只传技术引用。必须收到 stop、DONE 并完整读完 HTTP 正文，随后通过既有 schema 校验才算该次模型成功。断流不降级、不重试、不当作业务否决。配置、字段与恢复细节由 [概念 pipeline README](../preparation/concepts/README.md#模型-http-流式传输与边界) 和 [平台能力说明](../../demiflow/docs/prompt_http.md) 维护。

## 11. Token 与全批预算

P1、首轮 P2 和第二轮 P2 均使用 `malasci/gpt-6.1-sol`，没有 fallback 模型。P1 完整输入最多 8,000 tokens、输出最多 4,000；两轮 P2 完整输入分别最多 32,000、输出分别最多 8,000。输出上限是否包含推理 tokens 应按服务实际协议确认，不凭别名猜测。

完整输入计数应覆盖固定提示词、响应 schema、消息包装和业务载荷，采用经过确认的 tokenizer 与请求计数配置。不得把字符数或未经核实的相近模型 tokenizer 称为精确计数。服务仅列出模型名不足以证明上下文容量、编码器和价格；正式 HTTP 执行前必须配置并验证对应模型的计数与上下文档案。离线工程测试可以使用明确标注的测试档案，不能拿来推断真实账单。2026-10-01 的通用校准和六条正式 P1 表明，仅增加一个固定包装常数不足以解释真实 usage；不同 schema 长度会改变偏差。目前实测一致的口径是 o200k_base、每消息 3、角色文本正常计数、system 正文计数两次、user 正文计数一次、最终固定计数 6。role_content_copies 显式记录这一服务计数规则；它不证明上游实际注入了第二份系统消息。三次校准实际输入为 194、3,213、32,000，六次 P1 为 1,783–1,911，均与这一规则一致。32,000 输入和 8,000 输出额度的请求被接受，因此 40,000 是已测试准入范围，不是厂商最大容量。P2 及后续请求继续对照 usage 检查；网关默认 token_counter 不作为真实账单。

以下模型请求和 token 上界只覆盖客户端向所配置模型接口提交的请求；仅在下游没有额外重试或调用时，才可进一步解释为整条可控链的上界。此前网关默认重试已被实测确认；现流程显式关闭可控网关重试，但供应商内部行为仍不能据此推断，不能把这些数字当成实际费用硬上限。

设实际输入数为 N，在默认额度下，首轮模型最多 N 次、首轮审定最多 N 次、补查审定最多 N 次，共 3N 次。完整输入理论上界为 72,000N tokens，输出上界为 20,000N tokens；这不是预计实际使用量。逻辑搜索最多 6N 次，含一次技术重试最多 12N 次；不同 URL 获取尝试最多 25N 次，含一次技术重试最多 50N 次，重定向 HTTP 跳数另记。最多取得 10N 份可读文档。

模型调用预算按节点独立，并同时绑定到对应 SQLite 日志的原子预留限制，同 run 累计，已有完整响应复用不占新请求。预算不足保留状态行，不丢输入。不默认自动跨 run 搬模型缓存。实际费用需要服务价格和原生日志 usage；没有可靠单价与实测时不输出看似精确的金额或耗时。

## 12. 持久化、复用和恢复

每张阶段表由一个受控提交者写入，小批提交满足行数或时间条件，结束时刷新尾批。同一次交付检查稳定行 ID 唯一性；提交不确定时按 ID 与完整类型化内容核对实际落表结果，不能盲目重复追加。每次执行创建一个新的交付 head，再小批追加；旧固定版本保持可读。重跑通过固定输入及模型/取证日志回放当前交付，不是覆盖既有固定版本或宣称完成了跨存储事务。技术未完成的尝试与后续成功尝试有各自记录，当前结果明确选择最新有效运行状态，不把首次 pending 固定为永久结果。

顺序为：写入并核验独立对象；提交阶段行；验证写入回执；向下游释放。不存在跨文件、Lance 和 SQLite 的全局事务。提交结果不明确时先核对是否已经落表，不能直接再次 append。模型响应已保存但业务行未提交时，重跑复用原响应再提交，不新增付费调用。只有请求占位而没有明确响应的调用不能自动重发。

搜索和获取在同 run 内复用成功结果，并合并并发相同请求；共享结果仍保留各行的问题关联。正常无结果可以作为本次搜索事实复用，耗尽额度的技术失败另以失败回执保留，重跑不悄悄重置尝试数，也不冒充成功缓存。已预留但未取得完整回执的获取记录标为中断，刷新使用新的 run。新 run 默认重新取证；对象内容可以跨 run 按散列去重。若显式提供固定测试或复核材料，必须冻结其身份，不能跟随可变表头或线上 URL。

运行记录区分已完成、核验未决、未开始、输入无效、输入预算不足、等待离线响应、模型错误、取证技术未完成、补查技术未完成和协议无效。summary 的 complete 表示要求执行的步骤都得到有效交付，不表示全部概念成立、可出题或通过独立专家审核。

## 13. 业务与平台职责

| 事项 | demiflow 通用能力 | concepts 业务职责 |
| --- | --- | --- |
| 搜索/HTTP | 有界请求、重定向、字节限制、重试、技术状态、共享限额和复用 | 查询计划、候选配额、问题关联、补查优先顺序 |
| 文档 | 原子对象写入、结构化文档契约、解析及引用读取校验 | 支持格式选择、目录与问题相关片段编排、材料 token 配额 |
| 流式执行 | 队列、worker、背压、单写者小批提交与幂等恢复 | 主线节点顺序、每概念行粒度、条件补查 |
| 模型调用 | 实际请求构造、日志、计数与运行限额、无隐藏重试 | P1/P2 提示词、输出契约、结论检查、名称与身份边界 |
| 语义判断 | 不判定概念成立或材料可信 | P2 判断相关性、证据支持、冲突、范围和视觉潜力 |

不为尚未接入的历史 collect、图片下载、训练或评测构建空泛的总框架。当前真实消费者需要的能力补入平台并由本流程实际使用；其他采集链路在接入时按已登记计划标准化。

## 14. 验收与 review

工程验收覆盖正式 config → 主图 → 请求 → 校验 → 流式交接 → 持久化 → 恢复，而不只测试孤立辅助函数。必须测试：输入范围可配置；原名和别名桥接；QID/额外线索只读传入；普通科属不强改为种；错误别名不能导致程序硬过滤；多查询共享 URL 不丢问题关联；长文未读与补读；部分失败和全部技术失败；正常无结果；第一轮有效结论与第二轮失败共存；一次补查的各项额度；越权/未读引用；范围变化不可自动采纳；尾批刷新；同 run 复用；提交不确定后的核对；输出分母不丢失。

故障测试还覆盖并发上限、单主机速率、重定向/压缩大小/整体超时、429、服务连续失败停止、无模型自动重试、token 预算包含提示词/schema、对象缺失或散列改变以及源版本不匹配。失败测试不能联网请求生产模型。

真实模型质量验收另行执行：完成真实批次后，从有效审定中随机抽查 100 条（不足则全部），另查全部范围变化、冲突和结构/引用异常，分别报告随机与定向样本，不能混为无偏准确率。检查名称到对象的桥接、核心事实条件、视觉推断边界以及材料是否支持结论。所有报告明确实测样本、失败分母、尚未核实事项，不把 mock 测试通过写成 40 万数据已经可靠。

性能观测分别记录本次运行耗时、各算子处理耗时、队列等待、共享资源等待、模型 usage、搜索与获取的请求数/结果状态/字节量/延迟及补查比例。算子处理耗时不含其输入队列等待或向下游发送的等待；其中包含算子内部的资源准入等待。批提交者按每批计时，其攒批等待不算写入时间。并发阶段的累计耗时不能相加作为端到端时间。重名算子按拓扑分别编号，避免队列与统计错配。冷启动、同 run 缓存重放和校准调用分别报告，小样本不直接代表 40 万条稳定吞吐。

逐项 review、测试命令与实际结果、剩余限制及正式运行前需核实的服务信息统一记录在 [实现与复核记录](P1_P2_REVIEW.md)。本规范保留充分解释，代码和 README 使用同一组默认值与状态含义，避免继续维护互相矛盾的版本。


## 2026-10-01 多概念实测后的补充约定

用户要求提高验证预算。旧默认值和历史实测不追溯改写；当前正式入口的验证配置把 P2 输入上限提高到 64,000 tokens，输出仍为 8,000，首轮/新增/累计材料分别为 24,000/12,000/36,000。相同流式路由已通过 64,000 输入及 8,000 输出额度的真实准入校准。来源查询、下载数量、最多一次补查的逻辑上限仍保持，18 概念本次最多 54 次业务模型请求。完整输入的配置上界变为 136,000N，不是实际用量预测；额度不要求用满。

首轮必须为可能发生的第二轮保留上下文空间。业务配置 `supplement_context_reserve_tokens` 默认 12,000，当前扩容验证设为 16,000。平台只执行调用者传入的输入上限，不理解“第几轮”的业务意义。文档来源在 P2 载荷中按文档统一列出；正文用文档编号关联，证据短编号在业务结果落表前精确恢复为稳定引用。全量技术日志仍在原有回执和原生调用日志中，不能为压缩输入删掉原文、反证或上一轮判断。

每个概念仍取证，但并非每个概念都补查。P1 可以使用模型自身已有知识提出候选和核验问题；P2 采用的身份与核心事实需要实际交付的证据。正常可解释的主体加限定不要求逐字作为固定词条出现，也不要求恢复旧作者的心理意图；真正改变对象范围的歧义仍需保留。身份清楚且已有一个合格核心任务方向时，次要别名和旁支变体的未知不构成自动补查理由。仅在缺口可能改变当前身份、推翻核心事实或决定图像判据是否成立时补查，其他缺口明确记下。

读取策略增加跨文档份额，避免仅因问题使用中文而完全不交付已下载的英文资料；这是技术阅读分配，不是语义相关性筛选。解析器保护页面布局容器，页面标题只作元信息。每份原始页面、解析结果、实际阅读位置与模型引用仍可追溯。详细实测结论与尚未解决的限制以本轮质量报告为准。
## 2026-10-01 服务故障收尾补充

服务连续故障触发平台 `ServiceStopped` 时，停止新调度并保留本次失败状态。对有持久日志的原生模型调用，允许正在执行的请求在原超时内完成并保存响应或失败；流执行器只等待算子声明的有界收尾时间，超限强制取消。被取消行不得发布为完成，已有提交仍有效，未完成输入保留。用户主动取消不转换为继续运行。该能力属于 `map_prompt_async` 和 `run_stream`，业务不自行管理 HTTP 连接或复制调用日志。

真实验证、预算扩展、并发结果和搜索前置条件见 [多概念质量验证记录](P1_P2_多概念质量验证_20261001.md)。没有收到 usage 的取消调用属于费用未知，不能算作零成本。


### P2 v9 补读定位协议（2026-10-02）

真实全量中两条P2 v8响应在复制长SHA时漏字，严格校验保留invalid_response。现行P2 v9只通过supplement_requests.document_id选择本请求readings中已有D编号；search/fetch填写空字符串。业务在校验前将已知编号精确绑定到原document_ref，未知编号和模型自行提交document_ref均拒绝，不进行SHA猜补。持久Lance契约仍用完整ObjectRef，原模型响应仍在原生日志，第二轮输入把前轮已存引用重新映射到当前D编号。P1 v8、业务审定标准、来源/材料和完整请求预算保持；不同版本的实测分别登记，不能把v8质量记录混称v9通过。
