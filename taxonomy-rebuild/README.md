## 模型与执行的区别

分类判断由当前 Codex 会话完成，候选先按同类名称整理，再按分类展开复核，部分难例查阅资料。判断结果保存在 `combined-decisions.json`；它们不是独立专家审定结果。

脚本只回放已保存的判断：**没有模型 API 调用、没有再次调用 Codex、没有配置外部分类模型**。脚本回放不耗模型 token；本轮会话分析会耗 token，没有可审计账单时不填估算成实际消耗。

这是一份固定批次分类方案和文档导出工具，不是替换输入就能自动理解任意新概念的通用分类器。原树和概念均由 AI 生成，不能成为新树或 40 万概念的正确标签。全量接入设计见 [规范第 9 节](TAXONOMY_REBUILD_SPEC.md#9-不可靠旧树下的-40-万概念重建)。

## 真实来源与名称追溯

2026-09-30 已只读核对共同工作区 `datasets/master_concepts.lance@4`（385,292 行）和 `datasets/images.lance@16`（2,164,671 行）。两批 3,315 个名称全部精确匹配主表；逐概念旧路径存在于主表 `taxonomy`，先前粘贴文本未提供这些关系。该核对尚未改写已有判断快照或分类树。

后续方案区分结论并复用依据：共同审定核对身份、名称、核心内容与任务潜力；视觉树维护核对类别及挂载；正式出题检查具体任务。现有粗筛/精筛规则作为参照，不再默认每个模块都必须串行执行。名称有效不等于物种，也不等于 T2I 应保留。

改名时保留“规范概念身份 → 已确认原名 → 图片 `concepts` → SHA / URI”的关系，语义不变可以继续找回原图。主表目前没有稳定 `concept_id`，现有 `aliases` 也含混杂关系；第一版在独立表中按来源 URI/原名建立身份并保留规范名关系，暂不做跨原名合并。旧图只先作为候选，消歧、拆分和范围改变不能自动继承旧图通过状态；历史审核及原名不得批量覆盖。

完整字段、复用规则与验收见 [规范第 11 节](TAXONOMY_REBUILD_SPEC.md#11-概念清洗名称追溯与旧图复用v13)。后续已补充全量元数据统计、外部名称查询与 12 张实图个案检查，见上方案例报告；未写公共表、未发起额外模型批处理、未启动全量清洗。

## 重建与检查

在本目录执行：

```bash
../../env/bin/python build.py --combined
../../env/bin/python -m unittest test_combined_view -v
```

不传参数默认也是合并版。在共同工作区根可执行 `env/bin/python demiwtg/taxonomy-rebuild/build.py`；脚本按自身路径定位输入，与当前工作目录无关。

命令在写出前检查两批输入哈希、判断快照哈希、名称保全、来源关系、组别、ID、三层路径及每个概念唯一挂载。重复执行产生相同内容，只更新 08–10 的 Markdown、08 的树 JSON 和 `combined-validation.json`，不生成 CSV、不写正式主表。

9 项测试覆盖：输入变更不覆盖已有产物、未复核判断变更、改名、来源丢失、组别篡改、ID 重复、空路径、无证据升级物种核验状态、重复生成一致性与历史文件保全。测试检查工程保全，不给出语义准确率。
