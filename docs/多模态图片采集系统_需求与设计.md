# 多模态图片采集系统 —— 需求与设计

> 版本：v1（首个交付范围）
> 范围说明：本系统**只负责数据采集**，作为后续多模态模型数据准备的原始素材来源，**不包含模型训练**。

---

## 1. 目标与范围

1. 用户已有一批标签（tag），需要从公开图片来源获取图片，作为后续多模态模型数据准备的原始素材。当前阶段仅做数据采集，不包含模型训练。
2. 用户为每个标签提供**目标图片数量**和**可选 Query**，并配置允许的图片格式、最低宽高、单文件/总字节上限和**许可证 allowlist**。
3. 第一阶段只考虑四个互补来源：
   - Wikimedia Commons
   - Open Images
   - iNaturalist
   - Google Images / Bing Images / 百度图片等通用图片搜索引擎
4. 四个来源都必须投影为**统一 Candidate**，至少包含：`source`、`source kind`、稳定资产 ID、命中标签与 Query、`landing URL`、`content URL`、声明 MIME/宽高/大小、作者、`Credit`、许可证原始声明和来源响应证据（详见第 5 节）。
5. 系统应先获取并保存 Candidate 元数据，再按来源可信度、回源状态、URL 安全、MIME、尺寸、大小、许可证、标签配额和总预算筛选下载对象，**不能发现一个 URL 就立即下载**。
6. 法律边界：系统只保存来源声明并执行配置策略，**不提供法律结论**。注意区分四种不同判断：
   - “可以检索到”
   - “技术上可以下载”
   - “来源声明某种许可证”
   - “适合具体训练用途”
7. 首个交付只实现：**人工标签和 Query → Wikimedia API → Candidate 筛选 → 图片下载验证 → SHA-256 和 JSONL**。后续按 Open Images、iNaturalist、通用图片搜索与原站回源的顺序增加另外三个来源。

---

## 2. 输入配置（用户侧）

每个标签（或标签组）由用户提供：

| 配置项 | 说明 | 备注 |
| --- | --- | --- |
| 标签（tag） | 目标类别标识 | 必填 |
| 可选 Query | 用于检索的关键词/学名/物种名 | 可选，缺省时按标签名检索 |
| 目标图片数量 | 该标签期望采集数量 | 配额上限依据 |
| 允许图片格式（MIME allowlist） | 如 `image/jpeg`、`image/png` 等 | 全局或按来源覆盖 |
| 最低宽高（min width/height） | 像素阈值 | 不满足则在筛选阶段拒绝 |
| 单文件字节上限 | 单个文件最大字节 | 超限拒绝 |
| 总字节上限 | 全量预算 | 预算用尽即停采 |
| 许可证 allowlist | 允许的许可证原始声明集合 | 不在名单内则在筛选阶段拒绝 |

> 所有上限与 allowlist 以**配置策略**形式存在，作用于第 6 节的筛选阶段，不干预来源检索本身。

---

## 3. 数据源总览

四个来源在覆盖能力与身份/许可证完整性上互补：

| 来源 | 类型 | 适用标签 | 身份/许可证完整性 | 首交付优先级 |
| --- | --- | --- | --- | --- |
| Wikimedia Commons | 开放媒体目录 | 通用物体、人物、地点、建筑、历史文化、部分动植物 | 高（metadata 相对完整） | **首个可运行** |
| Open Images | 已有标注数据集 | Person、Cat、Dog、Car、Bicycle、Building 等固定 ontology 内常见视觉对象 | 中（依赖 release 标注） | 第二 |
| iNaturalist | 动植物领域来源 | 物种名/学名对应的动植物 | 中（需照片级许可证） | 第三 |
| 通用图片搜索引擎 | 长尾/开放词汇广召回 | 长尾标签、开放词汇 | 低（需原站回源验证） | 第四（含原站回源） |

---

## 4. 各来源详细设计

### 4.1 Wikimedia Commons（开放媒体目录）

- **用途定位**：作为开放媒体目录，来源身份和许可证 metadata 相对完整，因此作为**首个可运行来源**。
- **适用标签**：通用物体、人物、地点、建筑、历史文化和部分动植物标签。
- **检索方式**：通过 **Action API** 的 `File` namespace 按 Query 检索。
- **读取字段**：
  - page ID
  - File landing page（文件页）
  - 原图 URL
  - MIME
  - 宽高
  - 大小（字节）
  - 作者
  - Credit
  - 许可证元数据
- **下载与复验**：从 `upload.wikimedia.org` 下载并**复验图片**（解码、实际 MIME/宽高/大小、SHA-256）。

### 4.2 Open Images（已有标注图片数据集）

- **用途定位**：作为已有标注图片数据集，适合固定 ontology 内的常见视觉对象（Person、Cat、Dog、Car、Bicycle、Building 等）。
- **数据获取**：从**同一官方 release** 获取以下文件：
  - class descriptions
  - image labels
  - bounding boxes
  - image metadata
- **映射与索引**：
  1. 把用户标签映射为 **Class ID**；
  2. 建立本地索引：`Class ID → Image ID → 图片资源`。
- **必保存字段**：Dataset release、**Class ID**、**Image ID**、**split**、**annotation provenance**。

### 4.3 iNaturalist（动植物领域来源）

- **用途定位**：作为动植物领域来源。
- **解析流程**：
  1. 先把**物种名或学名**解析为**唯一 taxon ID**；
  2. 再分页查询**带照片的 observations**；
  3. 按 **photo ID** 形成候选。
- **必保存字段**：observation ID、taxonomy、作者、时间、位置、照片 URL、尺寸、**照片级许可证**。
- **许可证强制规则**（重点）：
  - **必须使用照片级许可证**，不得将 observation license 当作 photo license；
  - 不得把无版本的 `cc-by`、`cc-by-sa` 自动推断为某个具体版本（如 `cc-by-4.0`）。

### 4.4 通用图片搜索引擎（Google Images / Bing Images / 百度图片）

- **用途定位**：作为长尾标签和开放词汇的**广召回来源**。
- **接入方式**：
  - 优先使用**正式 Search API**；
  - 确需读取搜索结果 HTML 时，必须遵守服务条款、`robots` 和访问范围，**不绕过验证码、登录或反爬**。
- **搜索引擎结果处理**：只保存
  - 标题
  - rank
  - landing page
  - 图片 URL 或缩略图 URL
  - 形成 **SearchLead**。
- **回源验证（提升为 Candidate 的前置条件）**：
  - 必须访问**原始 landing page 或来源 API**，验证来源资产 ID、原图 URL、作者和许可证后，才能提升为可下载 **Candidate**。
- **禁止事项**：
  - 搜索引擎、搜索缓存和缩略图**都不能**记录为图片原始来源；
  - 无法完成原始站点验证的 SearchLead **不得进入下载计划**。

## 5. 统一 Candidate 模型

四个来源都必须投影为统一 Candidate，至少包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `source` | 来源名称（Wikimedia / OpenImages / iNaturalist / SearchEngine） |
| `source_kind` | 来源类型（目录 / 数据集 / 领域社区 / 搜索引擎） |
| 稳定资产 ID | 来源内稳定唯一标识（如 page ID、Image ID、photo ID、SearchLead 资产 ID） |
| 命中标签 | 命中的用户标签 |
| Query | 实际使用的检索词 |
| `landing_url` | 来源落地页 |
| `content_url` | 原图内容 URL |
| 声明 MIME / 宽高 / 大小 | 来源声明的媒体属性 |
| 作者 | 来源声明的作者 |
| `Credit` | 来源声明的署名信息 |
| 许可证原始声明 | 来源声明的许可证（原样保存，不推断版本） |
| 来源响应证据 | 来源 API / 页面的原始响应（用于审计与复验） |

---

## 6. 候选筛选与下载流程

### 6.1 两阶段原则

- **阶段一（元数据）**：先获取并保存 Candidate 元数据（第 5 节），不直接下载。
- **阶段二（筛选+下载）**：再按下列维度筛选下载对象：

| 维度 | 动作 |
| --- | --- |
| 来源可信度 | 低可信来源需更强回源证据 |
| 回源状态 | 未完成原站验证的不得下载 |
| URL 安全 | 校验 HTTPS/host 与逐跳 redirect 合法性 |
| MIME | 命中格式 allowlist |
| 尺寸 | 满足最低宽高 |
| 大小 | 单文件上限 + 总预算 |
| 许可证 | 命中 allowlist |
| 标签配额 | 不超过标签目标数量 |
| 总预算 | 总字节上限 |

### 6.2 下载器要求

下载器必须执行：

1. **HTTPS/host 校验** 与 **逐跳 redirect 校验**；
2. **per-host 限速**；
3. **timeout** 控制；
4. **429/5xx 有界重试**；
5. **流式字节限制**（防止超预算）；
6. **Pillow 完整解码**；
7. **实际 MIME / 宽高 / 大小复验**（与声明对比，不一致按策略处理）；
8. **SHA-256 内容寻址存储**（按 `images/sha256/...` 组织）。

---

## 7. 输出与产物

最终输出至少包括：

- **候选清单**（通过的 Candidate）
- **候选拒绝清单**（含明确拒绝原因）
- **下载成功图片清单**
- **下载失败清单**
- **每标签 / 每来源统计**
- **`images/sha256/...`** 图片内容（内容寻址存储）
- 每个**拒绝**或**失败**都保存**明确原因**

> 建议以 **JSONL** 形式保存各类清单与统计，与图片内容寻址路径关联。

---

## 8. 合规与法律声明边界

- 系统**只保存来源声明**并执行配置策略，**不提供法律结论**。
- 必须严格区分四类判断：
  1. “可以检索到” —— 检索可达性；
  2. “技术上可以下载” —— 网络/解码可行性；
  3. “来源声明某种许可证” —— 来源 metadata 中的许可证声明；
  4. “适合具体训练用途” —— 需要人工/法务判断，不在系统职责内。
- 许可证处理规则（强调）：
  - 一律保存**原始声明**，不自动推断版本；
  - iNaturalist 等来源必须使用**照片级许可证**，不混用 observation 级许可证。

## 10. 术语表

| 术语 | 含义 |
| --- | --- |
| Candidate | 统一候选对象，四来源投影后的标准结构（第 5 节） |
| SearchLead | 搜索引擎原始结果，仅含标题/rank/landing/图片URL，未验证 |
| 回源验证 | 访问原始落地页或来源 API 验证资产身份与许可证 |
| 内容寻址存储 | 以 SHA-256 命名/组织文件，去重并校验完整性 |
| annotation provenance | Open Images 标注的来源与归属信息 |
