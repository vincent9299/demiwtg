# 正式 200 前的出题与材料扩展操作规则

本文件是 DESIGN 第 16 节的实施手册，不修改长期设计，不代表正式题已准入。代码位于本目录；新材料、冻结批次与审核记录写入 `state/curation/knowledge_application_v1/` 的独立版本。旧 benchmark 两轨及既有题面、输出、分数保持只读。

目标是评估模型从可靠图文材料获取知识并应用到新图像任务的能力。BAGEL 加资料的提升、与闭源模型的差距是实验结果，不是正式题的准入条件。直接应用也属于目标；不能把所有任务改成答案已写明的绘图 caption。

## 1. 开工边界与现有入口

- 先读 `../DESIGN.md` 第 16 节及仓库 `AGENTS.md`。用户明确授权的操作优先；本文不授予新付费预算或正式冻结权限。
- `material_pool.py` 的 build/summary 和 `material_pool.json` 提供分域分支、稳定哈希的材料入口：每域 20 槽是筛选预算。580 域槽存在跨域重复，不能说成 580 个独立知识单元。优先保留部分有 docs 概念，同时检查无 docs 候选，避免供给偏差。
- `domain_cases.json` 是 29 域的有限样例或明确缺口审计。`reviewable` 只代表材料可提交审核；`gap` 只代表已检查的材料不足，均不等于领域整体结论。
- 当前 272 概念净版 docs 的覆盖是本机已接入范围，不能外推至全部概念、远程 Wiki 或持续同步资产。清洗通过、路径存在、哈希正确、概念关联都不等于事实或图片身份通过。
- 主域依据被考知识的实际语义审核，保留原挂载作溯源；不要修改 taxonomy 凑配额。一个题族只计一个主域，跨域标签另记。
- 29 域每域 6/7 题、四应用层次数量均为提案。两轨各 200、合计 200 或先 T2I 200 的数量口径未定；可继续材料和开发验证，停止数量相关正式抽样、冻结及全量调用。

## 2. 每个候选按此顺序制作，不从题目反向找证明

### A. 来源与身份

1. 选一个稳定概念、型号/物种/规则家族；记录原名、别名、原挂载、审核主域及 `knowledge_family_id`。
2. 实际读源片段与上下文，保存 URL、版本/日期、原文位置、短摘和支持范围。`page_sha` 常为 URL 哈希，不能当内容哈希；另记文件内容 SHA256。标准必须有版本，产品必须有具体型号/修订范围。
3. 实际看每张拟用源图，记绝对路径、SHA256、来源页、图注、身份依据、可见部位及不支持的判断。不得从普通外观推断成分、内部机制、真实性别或特定月龄。
4. 分开记录事实可靠性、策展价值和图片支持。机器摘要、盲 caption、图片关联和旧人审标签均不能替代三项独立核验。发现来源矛盾，先缩小或暂停争议判据，不能择一隐藏另一条。

**通过**：每项拟考事实有可定位依据，适用范围无未解决实质冲突，必要图片身份及部位可检查。**停止**：仅有搜索摘要/网页壳、错误概念绑定、来源缺失、图片不支持关键部位，或权利/访问限制尚不能满足拟定用途；记录具体缺口和下一份所需材料。

### B. 条件、选择、应用与可见结果

逐项填写简短记录：`given → selected source/fact IDs → application relation → visible result`。这是可审计关系，不索取或储存模型长篇自由思维链。

- `direct`：型号/概念选择其已知形态，迁入新的自然场景。例如型号选择双叉槽及面板布局；不是只有识别标签。
- `conditional`：题面给必要阶段、版本、介质或环境，从规则/状态中选适用事实。邻近条件对必须由来源确实支持不同结果；不擅补阈值等号。
- `relational`：事实决定对象之间的位置、接触、支持、排出或过程关系。每个参与对象都有角色；仅同时出现两对象不等于应用了关系。
- `compositional`：至少两条必要事实共同约束同一结果或相关对象；明确各事实贡献。堆物体、文字、跨域标签不算组合知识。

六类内容标签独立多选：特征与结构、属性与状态、关系与组织、过程与变化、功能与机制、规则与约定。主应用层次单选，不恢复 L1/L2/L3 的跳数、前提数、跨域数门槛。

**通过**：删掉知识材料仍有明确原任务，但至少一项可见结果须由概念或知识补足；条件足以排除实质歧义；关系本身有来源。**停止**：答案全写入前提、结果只是执行所给颜色/文字、因果由出题者猜测，或关键效果无法静态观察。不要把“出题模型觉得长尾”当实测难度。

### C. 先冻结可见判据，再迁移为任务

每个 K 项写 `criterion/source_ids/observable_region/exceptions`，注明什么情况下 pass、conflict、unobservable。合法集合保持开放，避免精确色值、微斑数、固定比例等来源未支持要求。食物允许来源支持的其他小昆虫/卵；猪鼻龟两性尾长比较不强制尾宽。

然后写原题：给身份、必要条件、场景与观察视角，不直给被考结果。T2I 将知识迁到新背景/姿态/容器；编辑绑定实际原图、目标锚点、允许变化及非目标保持项。新场景不得破坏事实条件。检查目标在实际输出尺寸是否够大；看不清的口器、尾部不靠想象评分。

将要求拆为四组：知识 K（包括足以限定目标身份的结构组合）；显式执行与数量；编辑背景保持；画质。粗层主体缺席属于执行失败；已经画出龟但物种特征错，属于身份知识错误，不反复算成通用执行错误。不要添加无用途的全机完整、无文字或复杂视角义务。冻结后发现判据超出题面，保留原分并另发统一适用的补充协议，不无痕改分。

本轮复验暴露了最低身份约束的必要性：深色、分节、橙斑不足以排除毛虫式错误幼体。下一版瓢虫判据应引用已核验来源中的鳄鱼状体形及胸部三对足，检查足的区域和整体体形，不能只检查颜色。猪鼻龟需用实际鳍肢参考区分鳍与多趾蹼足，提供通过/冲突/看不清边界样例；不能把普通龟加一个猪鼻称整体正确。新增判据进入下一冻结版本，当前局部K成绩和语义复核同时保留。

**通过**：助手能凭给定来源和图判断每项，存在合理可绘制实例；没有唯一标准像素图也可通过。**停止**：判据自相矛盾、目标被题面遮挡、来源只支持另一条件，或任务主要被无关绘制负担支配。退回前一步改版本，并保留失败草案。

## 3. 三种证据形态按充分性矩阵判定

逐 K 分别审核完整现有文字、实际图片、二者合用的支持范围；记录缺失的信息，不以模型分数反推材料充分性。

| 形态 | 准入依据 | 不可作的替代 |
|---|---|---|
| 文字主导 | 原文足以支持核心 K；图可以辅助身份或场景 | 有一张普通关联图便称图像知识 |
| 图像主导 | 正常源图支持核心形态；完整现有说明没有相应细节 | 人为删短文字、把目标答案图当源图 |
| 图文严格互补 | 文字提供必须的条件/选择关系，图片提供必须的形态/空间信息；任一单模态都不能独立支持全部核心 K | 文字已完整给答案，或图片表格含全部规则，却仍称互补 |

NGT VX1 开发例是**相对完整现有商品说明的图像主导**：源图支持双叉深槽、圆面板与底部螺杆；功能说明不描述这些外形。不能宣称这些形态永远无法用文字描述。商家来源与历史修订覆盖仍有限，粗 K 也不足完整鉴定型号。

首轮该例审核显示：图上正确结构可以与违规携带盒同时出现；另有一般报警器满足双叉槽却缺正确面板/螺杆。知识、身份/执行和质量必须分别留记录，不因符合研究假设而改判。此例及已用开发家族不进入未见正式集。

**当前缺口**：现有材料尚不足证明已形成稳定、来源充分的图文严格互补题族。下一候选需正常文字说明选择哪个状态/部件/版本，再由独立源图确定必须画出的结构；先证明双方各有不可替代支持，后做单模态消融。不要为了三栏都有数量硬贴标签。

## 4. 替换历史 synthesis 的具体输入与门槛

以下是新实现的迁移要求，不直接改动或重新运行旧批次。

| 历史部位 | 新版替换项 |
|---|---|
| `benchmark/t2i/eval_synthesize.py` 概念名、路径驱动，模型提供知识 | 输入已审核证据包；输出每个 K 与来源 ID 绑定；缺证据返回具体不可出题原因 |
| T2I v6.0 的路径首段作为主域 | 原挂载只作线索，另填经语义核验主域 |
| T2I v6.0 / edit v6.1 强制跳数、前提数、跨域、弱点组合及补峰 | 四应用层次与独立知识内容/证据形态统计；覆盖不足补材料，不为达复杂度添义务 |
| 出题时推理记录，生产判分仅靠通用判官知识 | 来源绑定 K、必要应用关系和例外进入评分包，执行与画质保留 |
| 编辑仅看原图与动作 | 增加源知识、明确原图目标锚点、可编辑项和保持项，拒绝把参考外观当安装关系证据 |
| 只有一个模糊“图片输入” | 用显式角色、顺序、哈希和版本绑定原图及多张资料；实测接口后才宣称支持 |

可沿用严格前提、像素可核验、自然场景和不可出题分支。不能只换 prompt 文案却仍由旧脚本用旧量化门槛拦截或选题。

## 5. 检索与材料扩展的下一步

1. 对材料池候选先查本机净版、源页、已有关联图和预标注索引。缺图与错知识分开；存在但不显示目标部位与文件缺失分开。
2. 为每项缺口写检索需求，例如特定幼体阶段、型号独立照片、原标准表页、正常安装接触关系。优先修本库错绑、缺同步、未纳入索引和截断问题，再扩外部数据。
3. Wiki 下载用于扩大可检索正文和跨域覆盖；保留修订/来源与内容哈希、去站点外壳及近重复。Wikidata 用于实体消歧与带限定关系，Commons 用于关联原图、图注及逐文件权利信息。三者均不能自动认证物种身份、因果或满足图文互补；不等全量下载才审核现有材料。
4. 对实际 top-k 逐 K 记录 `supported/partial/unsupported/conflicting`、rank/index、确切短摘和解释。原判据仍由审核源决定。报告源未入库、入库未召回、召回被截断、错绑噪声及相邻冲突，不把命中源 URL 算支持通过。
5. `pilot/retrieval_support_review.json` 已说明页命中与 K 支持不同；旧 Wiki 尾宽叙述等相邻冲突不可默认可信。该离线检索审计不等于已运行 retrieved generation。

**扩量闸门**：只有解决了具体缺口的材料进入下一批审核；未完成下载/接入/身份核验的资产仍标待接入或待核验。补材料的选择不按 BAGEL/Gemini 成败排序正式集；开发可以诊断失败，但保留其开发归属。

## 6. 开发验证、正式准入与停止条件

- 开发批先冻结原题、K/例外、证据版本、角色、模型实际输入、预算和重复策略。无资料、完整文字、图片、图文使用同一原题；oracle 手选资料与实际检索分别命名。
- 显式目标 caption 只作“知识选择/转换还是绘制失败”的诊断臂。规划/编译器输出、原生资料输入分别保留；不得用 caption 替代失败资料臂再宣称 RAG 成功。
- 全部输出及失败留存。实际逐图看原图和评分资料；无图 K 全部不可观察、执行 false、质量 null。有图不把目标缺席计为否定判据通过。
- 报告逐 K、可观察率、执行/保持、质量、联合通过，并按域、应用、证据形态分层。匿名助手审核不叫人工金标准；重要正例、争议和边界需独立复核并保留分歧。
- 正式准入依据：来源可靠与范围明确、知识应用链成立、原题不泄答案、可观察且合法集合可判、隔离检查通过。**不查看或使用 BAGEL/Gemini 输赢、原题失败、RAG 增益作为正式准入分数。**
- 正式冻结前停止条件：数量口径未确定；必需材料/接口角色未验证；严格互补覆盖只是贴标；泄漏/近重复未处置；事实冲突影响主 K。列缺口继续独立材料工作，不能用开发成功替代闸门。
- 正式冻结后发现事实或可判性错误：留原版本，公开排除/更正理由与影响范围；不能用“模型都错/没提升”替换题目。新种子或背景复验仍是开发已见知识，不称未见泛化。

## 7. 训练 tuple 与隔离清单

每条训练记录至少保留：`original_task + edit_source（若有） + source_materials + evidence_selection/application_links + verified_target + target_review`。选择/应用关系只记录必要事实与约束，不全部压成显式答案 caption。

资料对象分别标记：`retrieval_reference` 可检索真实源材料；`evaluation_evidence` 判分来源；`edit_source` 待编辑场景；`training_target` 已核验目标。一个源资产可以有多项已声明用途，但训练目标不能以改名成为资料。记录每次实际调用的角色、顺序、哈希与版本；不要靠数组位置暗示。

1. 切分之前合并同概念别名、产品型号家族、规则家族、来源转载/翻译、图像裁切/重编码等近重复组；先分组再划开发、训练与正式测试。
2. 本轮用于调 prompt、编译器、检索器或判据的家族全部留开发。换场景、换随机种子或换来源镜像不解除隔离。
3. 测试原题、答案 caption、目标图及近重复目标不得进入训练或资料库。允许从预先固定知识库检索未训练概念的真实源资料，这是知识获取协议，不等于允许检索本题合成答案。
4. 目标图无论真实、合成或闭源输出，都需独立核对 K、身份、执行、编辑保持和画质；生成图不是事实来源。未达标目标保留失败，不进入正样本。
5. 错配资料可单列受控负样本，明确错误性质与预期拒绝/纠正行为，不混入可信知识。错误资料导致同样错误只是输入影响证据，不是知识正确使用。
6. 实训后分别报告 BAGEL、BAGEL+资料、规划/编译器+BAGEL、微调无资料、微调有资料；闭源原题与同资料条件另列。未训练不得报告训练增益，图文 oracle 成功不得报告真实检索成功。

本轮交付应是可追溯材料与方法、开发观察及未解决缺口。能够扩量审核与构建受控训练 tuple，才进入下一阶段；不要求先宣称追平闭源，也不以追平承诺换取数据质量。
